# 考勤组配置及成员只读查询

HTTP：`POST /api/v1/business/attendance-groups/query`，现有 `ApiResponse` 包装。
聊天工具：`query_attendance_groups`，仅处理考勤组配置及配置成员。
聊天 SSE 直接推送回答模型生成的增量文本，完成后才保存完整回答与会话状态；
生成中断通过错误事件收尾，不把片段保存为完整业务回答。
参考旧系统 `attendance/attGroupConf/getConfList` 和 `attendance/attGroupConf/getGroupConf/{id}` 的读取语义，
不调用旧服务的写入或修改接口。

## 固定边界

- 请求必须有唯一真实 `projectId`、`segmentId`；模型不生成 ID，后端映射最近真实候选。
- 项目确定后，未指定标段且标段不超过 3 个，直接逐标段查询；超过 3 个先报总数和例子，询问全部或前 N 条。
  指定标段或组名、时段、地点等条件时，按指定范围查询，不另问是否确认查询。
- 项目 `project_stage='组织实施' AND del_flag='0'`；默认年度为北京时间当前年。
- 标段 `del_flag='0'` 且属于该项目；考勤组必须同属于项目和标段。
- 考勤组 `del_flag='0' AND att_status='1'`，指定日期在起止日期内（包含首尾）；
  省略日期为北京时间当天，缺有效日期的配置不返回。
- 不按当前钟点过滤。指定单一时刻时判断落入配置时段（含跨午夜），完整时段则精确匹配起止时刻。
- 成员和关联单位/岗位均过滤已删除记录。岗位编码重复时聚合岗位名称，防止人数放大。
- 参数化 SELECT、业务只读可重复读事务，不写业务库、不迁移结构。

本适配器的范围为已确定的项目/标段，不模拟旧系统登录角色和租户权限，
不能替代旧系统权限校验。

## 展示及承接

- 不指定某组时查询所选标段下符合条件的各组；同名组不合并，通过日期、时间、地点区分。
- 不超过 3 个：返回全部配置、完整成员。
- 超过 3 个且未明确范围：返回总数及最多 3 个真实例子（名称、日期、时段、地点），
  暂不加载完整成员；询问全部返回还是前 N 条，也可选择例子或补充条件。
- 明确全部/前 N 条后按范围读取，不分页、不截断成员。
- 每组默认展示配置、全部成员姓名，以及“纳入本考勤组 X 人，需要考勤打卡 X 人”。
  两个人数按有效成员配置记录计数，与旧成员列表口径一致，不是其他业务统计。
- 成员单位、岗位等完整字段保留在后端当前会话，默认只将姓名交给回答模型；
  用户追问单位、公司、岗位或人员详细汇总时再提供明细。单位使用 `unitName`，不虚构额外公司字段。
- 项目/标段选择期间保留原问题的组名、日期、时间、地点；后续成员详情保持已返回的真实组范围。
- 全量事实过长时分批交给同一模型组织并拼接，保留顺序，不静默省略记录。
- 会话状态在原 RAG 库已有 `conversation_state` JSONB 中，不使用 Redis 或业务库保存上下文。
- 内部 ID 只在后端，交给回答模型前递归移除；项目简介默认带年度、区县、投资金额（万元）。
  用户不展示金额等字段时先按字段投影，再交给模型组织，不改变完整快照。

## 会话快照与变更

- `projectQuery` 保存当前项目/标段真实选择及候选顺序，`attendanceScope` 保存当前筛选、所选组及待办范围。
- `querySnapshots` 保存实际请求、完整响应、首次读取时间。数据复用不会重置读取时间。
- `business.conversation.snapshot-ttl-seconds` 默认 300 秒；同条件且未过期优先复用。
- 成员详情、已读取范围内序号选择无需重新查成员；三个轻量示例不等于已读取完整结果。
- 新条件补查；项目/年度切换清除旧从属状态；标段、日期、组条件变更不使用不匹配快照。
- 取消指定名称/时段/地点筛选只清除对应条件，不误清除其他条件；展示偏好按字段分别保存，可单独恢复。
- 默认今天/昨天等保留相对日期表达，跨北京时间日期自然产生新请求；刷新或最新要求强制重新读取。
- 成员详情沿用已返回范围，但不把该范围永久当成组 ID 筛选；刷新可发现范围内新配置的组。
- 路由失败/短澄清不清除已选对象；明确新话题阻断旧范围。每轮保存新状态，不覆盖历史消息。
- 完整快照不交给路由模型，仅投影当前范围、真实显示顺序；回答只拿本轮允许展示的数据。

## 请求

```json
{
  "projectYear": 2026,
  "projectId": "实际项目ID",
  "segmentId": "实际标段ID",
  "groupName": "考勤组",
  "attendanceDate": "2026-11-12",
  "attendanceTime": "08:00-18:00",
  "location": "东荆",
  "returnChoice": { "all": true }
}
```

项目/标段 ID 必填，须为正 bigint 字符串；组名、日期、时间、地点、年度均可省略。
`groupIds` 为可选组 ID 列表，与固定归属和有效条件取交集。
名称/地点不超过 200 字，日期为 ISO 格式；时间支持 `HH:mm` / `HH:mm:ss` 或完整时段。
`returnChoice` 省略使用默认规则；`{"all":true}` 全部；
`{"count":5,"all":false}` 前五条，正数且不能与全部同时指定。

聊天使用原文参数 `projectYear`、`projectName`、`projectSelection`、
`sectionName`、`sectionSelection`、`groupName`、`groupSelection`、
`attendanceDate`、`attendanceTime`、`location`、`returnScope`、`memberDetails`、
`refresh`、`clearFilters`、`displayPreference`，
不向模型开放 ID、SQL 或直接条数参数。

## 响应

- `resultStatus`：`OK` / `EMPTY` / `NEEDS_RETURN_CHOICE`。
- `appliedFilters`：实际项目/标段、年度、组条件、日期、固定状态、删除标识、时区。
- `totalCount` / `returnedCount`：符合条件组总数 / 本次完整返回组数。
- `examples`：待确认范围时的轻量配置；`items`：本次完整返回的配置及成员。
- `memberCount` / `requiredMemberCount`：有效配置成员数。
- `memberUsers`：全部成员记录 ID、组 ID、人员 ID/姓名、单位 ID/类型/名称、岗位编码/名称。
- `notice` / `dataAsOf`：读取口径及快照时间；时长为小时，打卡范围为米。

HTTP 是完整数据接口，实际返回项包含全部 `memberUsers` 字段；
聊天的默认投影不删除后端响应和会话中的完整成员。
