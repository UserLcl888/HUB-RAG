# 项目及关联标段只读查询

HTTP：`POST /api/v1/business/projects/query`，使用现有 `ApiResponse` 包装。
聊天工具：`query_construction_projects`，同步及 SSE 聊天共用同一 Java 查询服务。
最终回答由大模型自然组织，真实条件、候选和是否追问由后端决定。

## 固定查询边界

所有项目查询均强制 `farmland.project.project_stage='组织实施' AND del_flag='0'`。
标段固定读取 `farmland.cp_bid_section`，强制 `del_flag='0'` 且关联匹配项目。
名称、ID、年度或候选选择都不能取消这些条件。
“施工中”采用组织实施阶段口径，不另外筛 `jszt='1'`。
年度未指定时按 `Asia/Shanghai` 动态取当前年，不永久写死某年。

业务库只执行固定、参数化的 SELECT，使用独立数据源的只读、可重复读事务。
不写业务库，不建表、迁移或修改数据，不允许模型提供 SQL、表名或数据源。
当前会话条件及候选保存在原 RAG 库已有 `conversation_state` JSONB 中；
不使用 Redis 答案缓存，不需要数据库结构迁移。旧分页版本上下文不再承接。

## 展示与追问

- 匹配项目不超过 3 个：可返回项目详情。名称有歧义或只有一个模糊候选仍须确认。
- 项目简介同时提供标段数量和真实标段名称；每个项目不超过三个名称时全列，
  超过三个只列最多三个名称示例并标记未列全，不提前加载标段详情，也不跳过项目选择。
- 匹配项目超过 3 个且用户未指定范围：只返回真实总数和最多 3 个轻量名称示例，`items` 为空；
  不加载这些项目的详情或标段详情。询问全部返回还是返回前 N 条，也可选择示例或补充名称。
- 项目已明确后，匹配标段不超过 3 个时返回标段详情。
  超过 3 个且未明确范围时只返回总数及最多 3 个标段名称示例，具体 `sections` 为空并追问全部还是前 N 条。
  标段名称有歧义或模糊命中也须先确认。
- 标段的三条限制应用于本次项目范围内的标段匹配总数，不按每项目分别凑满三条。
- 示例不是全部，不提供默认页、页码或翻页。用户明确要求全部或前 N 条后，按指定范围返回。
  明确选择“这三个”仅表示选择实际展示的三个示例。

## HTTP 请求

无请求体或 `{}` 查询当前年度组织实施阶段项目。

```json
{
  "projectYear": 2026,
  "projectName": "武汉经济区东荆街东荆"
}
```

请求字段：

- `projectYear`：整数 1900～2199；省略取当前年。
- `projectName`：用户原始项目名或简称，2～200 个有效字符；空白不筛名称。
- `projectIds`：可选非空正 bigint 字符串数组；与年度、阶段、名称取交集。
- `sectionName`：可选标段名或简称，不超过 200 字；只在匹配项目内检索。
- `sectionIds`：可选非空正 bigint 字符串数组；与项目及标段名称条件取交集。
- `projectReturn` / `sectionReturn`：省略采用默认三个以内完整返回规则；
  `{"all":true}` 全部，`{"count":5,"all":false}` 前五条，正数且不能同时指定全部和条数。

HTTP 可传已知 ID，但不能越过固定条件。
聊天不向模型开放 ID 参数，只允许后端将当前会话真实候选映射成 ID。
`business.project-query` 仅保留 `fuzzy-min-score`；默认三个示例规则在后端，用户可指定范围，不配置页大小。

## 匹配与多轮选择

项目先完整名称匹配，再规范化名称包含匹配，最后使用字符二元组和字符覆盖率召回相近项目。
不写死城市别名、不依赖数据库扩展、不让模型猜正式名称。
标段同样支持规范化包含及相似召回。

候选顺序原样保存在当前会话；“第一个”“第二个和第三个”“东荆那个”只定位最近展示的真实候选。
最近追问标段时，裸序号承接标段，不误选项目；项目与标段分别保存候选。
用户说“不在这些里面，我要某某项目/标段”，提取其新名称重新匹配，而非只搜索三个示例。
仅说“不在其中”时追问具体名称；否定句不能被当作确认示例。
更换年度重新检索，不用旧年度序号。切换其他话题后不复活旧候选，不跨会话引用。

项目指代解析由业务工具共享：上一轮展示项目后，本轮问“第一个项目的考勤组情况”，
按真实候选顺序解析项目，同时按当前诉求切换到考勤工具，不误回项目详情工具。
已解析项目和年度保留在当前会话上下文，后续“这个项目”可继续承接。
考勤组查询在标段不超过三个时自动逐标段读取，超过三个才追问范围，详见 `ATTENDANCE_GROUP_QUERY_API.md`。

工具白名单文本参数：

- `projectYear`：四位年度或原词“今年/去年/前年/明年”，由后端计算。
- `projectName` / `sectionName`：用户原始名称，保留错字，不补全正式名称。
- `projectSelection` / `sectionSelection`：本轮原话中的选择或承接动作，不继承重放上一轮动作。
- `returnScope`：本轮范围原话，如“全部返回”“前五条”，后端解析，不接受模型生成数字/布尔值。

## 响应

- `resultStatus`：`OK` / `EMPTY` / `NEEDS_SELECTION`；项目为空才返回 `EMPTY`。
- `matchMode`：项目年度、完整名称、包含或模糊匹配。
- `appliedFilters`：实际年度、项目及标段名称/ID、固定阶段/删除标记和时区。
- `summary.totalProjectCount / totalSectionCount`：项目匹配总数及其全部有效标段数。
- `summary.matchedSectionCount`：标段筛选命中总数；尚未进入标段匹配时为 null。
- `summary.districts`：匹配项目的所属区县统计。
- `items`：默认不超过三个，用户明确范围后按范围返回项目详情，包含名称、年度、项目编号 `xmbm`、代码 `xmdm`、区县、
  阶段、状态、面积（亩）、总投资（万元）、进度、建设地址和主管部门。
- `items[].sectionCount`：该项目全部有效标段数，不受本次标段名称条件影响。
- `items[].sectionNames / sectionNamesTruncated`：简介所用真实标段名称及是否仅为示例；
  项目尚未确认时也提供，不代表已查询对应考勤组。
- `items[].sections`：已明确范围的标段详情，默认不超过三条，包括名称、编号、单位、日期、
  原始状态、合同/中标金额（元）、建成面积（亩）。
- `candidates / sectionCandidates`：本轮真实项目/标段候选，默认最多三个，明确范围后按范围返回。
- `selection.scope / reason`：`PROJECT_DISPLAY` / `SECTION_DISPLAY` 等待返回范围；
  `PROJECT` / `SECTION` 等待对象确认，以及追问原因。
- `notices / dataAsOf`：统计口径、限制与快照时间。

`sections` 为空不一定没有标段，应同时看总数、匹配数及选择状态。
ID 使用字符串，标段号 `"01"` 保留前导零；未知状态不猜含义，空值不伪造。
项目和标段分开计数，避免一对多 JOIN 造成项目数翻倍。

会话查询快照及内部 ID 展示投影与考勤组工具共用，不使用 Redis。
