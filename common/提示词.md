### 1.2 纯文本版（模板渲染后的实际效果，便于理解）

```
【回答规则】：
1. 只基于上面的参考内容回答，不使用自身知识进行推测或补充
2. 回答中每条信息后面标注来源，格式：（来源：[参考N]）
   例如："年假为5天（来源：[参考1]）"
3. 如果多条参考内容都涉及，可以引用多个：（来源：[参考1][参考2]）
4. 如果参考内容不包含答案，回答："在知识库中未找到关于[问题要点]的信息。"
5. 禁止编造，禁止说"根据我的了解"、"通常情况下"等推测性表达
6. 保持信息完整性：参考内容中的步骤、列表、编号条目必须完整列出，禁止省略或合并概括
7. 如果参考内容包含具体流程或操作步骤，按原文顺序逐条列出，不要用一句话笼统带过
8. 回答用 Markdown 组织，结构固定为三段：
   第一行是以 ## 开头的二级标题，用一句话概括问题主题，不超过 20 字；
   第二段是结论或总述，2 句以内，先回答"是什么 / 分几类"；
   之后分点展开，不要写成大段文字。
9. 层级必须分明，最多三层：
   第一层用有序列表（1. 2. 3.）列出大类；
   第二层用无序列表（-）列出子项，缩进 3 个空格；
   第三层用无序列表（-）继续缩进 6 个空格；
   每个条目的要点用 **加粗** 标出，加粗后接冒号与说明。
10. 只有命中第 4 条（未找到答案）时例外：只回那一句话，不要加标题、不要列表。
```

### 1.3 为什么第 8/9 条要写成这样

| 写法 | 原因 |
|---|---|
| 明确要求 `##` 二级标题 | 前端解析器把 `##` 渲染为 `.md-heading`（15px/700）。若只写「用一个标题」而不给语法，模型可能输出 `**标题**`，那只会变成**加粗段落**，层级弱一档 |
| 标题限「不超过 20 字」 | 防止模型把整段话塞进标题行 |
| 「2 句以内」的总述 | 对应参考文档的「层级分明、结论清晰」——先给结论再展开 |
| **显式写死缩进空格数**（3 / 6） | 解析器按行首空格数判层级；模型自由缩进容易出现 1 空格或全角空格，虽已兼容但不如写死稳妥 |
| 第 9 条「加粗后接冒号」 | 与现有回答风格一致（`**农田防风林工程**：…`），解析后是「加粗 + 冒号 + 说明」的整齐观感 |
| 第 10 条例外 | 避免「未找到答案」时也硬套标题+列表，输出一个只有一句话的畸形文档 |

【解析器规格（src/utils/markdown.ts）】
导出类型：
  export type Inline = { text: string; bold?: boolean; italic?: boolean; code?: boolean }
  export type MdListItem = { inline: Inline[]; children: MdNode[] }
  export type MdNode =
    | { type: 'heading'; level: number; inline: Inline[] }
    | { type: 'paragraph'; inline: Inline[] }
    | { type: 'quote'; inline: Inline[] }
    | { type: 'list'; ordered: boolean; items: MdListItem[] }

导出函数：parseInline(text): Inline[]、parseMarkdown(source): MdNode[]

支持的语法（只做这些，不解析表格/链接/图片/HTML）：
  - ^#{1,4}\s+      标题
  - ^\s*(\d{1,2}[.、)]|[-*+•])\s+   列表项
  - ^\s*>\s?        引用
  - 空行            段落/列表分界
  - 其他非空行      段落

行内正则：/(\*\*[^*]+\*\*|`[^`]+`|\*[^*\n]+\*)/g

嵌套判定必须按以下三条规则实现：
  规则 1（缩进优先）：以行首空格数判层级，制表符与全角空格（\u3000）都折算为 2 空格。
        用「列表帧栈」实现：每帧记录 { indent, ordered, list }。
        遇到新列表项时，先把栈中 indent 大于当前项的帧全部弹出。
  规则 2（标记类型变化兜底）：模型经常不给子项缩进就换标记类型（1. 下面直接写 -）。
        若栈顶 indent 与当前相同但 ordered 不同，则在栈中反向查找
        「同 indent 且同 ordered」的祖先帧；找到就回退到那一帧（保证 1. → - → - → 2. 正确收尾），
        找不到就新建一层嵌套列表。
  规则 3（顶格段落结束列表·重要）：行首无缩进的普通文本行意味着此前的列表已结束。
        实现为：在累积段落的第一行时，若行首缩进为 0，则清空列表帧栈，段落挂到顶层。
        若不实现这条，回答末尾的总结句会被错误地吞进最后一个 <li> 里。
        （这是对 CommonMark 懒惰续行的有意偏离。）

段落归属：列表打开时挂到最内层最后一个列表项的 children，否则挂到顶层 blocks。

降级要求：不认识的行原样作为段落输出，绝不丢字；未闭合的 ** 正则匹配不上就保持字面显示。

【渲染组件规格（src/components/MessageBody.vue）】
props: { text?: string; nodes?: MdNode[]; streaming?: boolean }
